# Backtrack 设计与 TODO

本文记录已确定的行为边界、与 dynamic-skill 的协作方式及实现决策。核心实现和真实 SDK 测试已完成；当前状态见第 10 节，开发中发现的 SDK 约束与处理决定见第 12 节。

## 1. 目标与非目标

Backtrack 让 Agent 在长程任务中主动收起已经消化的探索过程，以指定 checkpoint 为边界调整模型上下文并继续执行。

行为类似 compact：**session 中的对话历史连续追加，改变的是模型使用的有效上下文，而不是 session 的历史位置。** 不切换分支、不把 session leaf 移回 checkpoint，也不创建新会话。

三个核心能力：

1. Host 自动建立 checkpoint，并在对应上下文位置提供可见地址。
2. 随 checkpoint 提供上下文容量反馈，辅助 Agent 判断回退时机。
3. Agent 调用 backtrack，Host 完成回退、交接和自动续跑，不要求用户再次输入。

采用 Kimi SendDMail 的逐步边界思想；历史与上下文分离的行为参考 Pi compact。原始探索记录仍留在当前 session 的连续历史中。

初版不做：

- 文件、进程、Git 或其他外部状态回滚。
- 通过 `/tree`、fork 或历史截断实现 backtrack；用户主动使用这些原生能力的兼容性另行处理。
- 任意中间区间压缩；初版只处理目标 checkpoint 之后的后缀。
- 额外调用模型生成交接摘要；续跑 message 由发起 backtrack 的 Agent 撰写。
- backtrack 自建知识库、保存知识条目或管理其展开与折叠；知识由 Agent 在回退前通过 dynamic-skill 固化。
- 归档搜索工具、摘要质量评估和缓存费用优化系统。

## 2. 功能独立，包层面关联

保留 `pi-dynamic-skill` 的普通包依赖，但把两者当作独立功能实现。

| 功能 | 职责 |
| --- | --- |
| backtrack | checkpoint、回退事务、续跑 message、模型上下文同步、自动续跑 |
| dynamic-skill | 知识固化所用的技能树、技能访问统计、LRU、技能列表及其更新提示 |
| 协作接口 | 回退生命周期通知、结算准备与提交、追加技能状态更新 |

约束：

- 包依赖继续保留，用于两者协作；backtrack 不再调用 createSkill 自动保存会话知识，也不直接读写 dynamic-skill 的队列或内部状态格式。
- dynamic-skill 自己决定哪些访问有效、如何结算和如何生成更新提示。
- 包已安装不等于扩展已启用；没有启用 dynamic-skill 扩展时，backtrack 仍应具备独立回退能力，但不能声称已固化知识，也不自动降级为自有知识存储。需要保留尚未保存的知识时，应先完成保存再回退。
- 两者同时启用时，成功 backtrack 是与 reload、compact 类似的技能结算边界。这是核心协作要求，不只是保存技能的提示。
- 不以调用一次 `/reload` 或伪造原生 compact 事件代替集成，避免重载整个运行时或误触其他扩展。

## 3. Checkpoint 语义

- 非零 checkpoint 指向下一次模型生成之前的上下文边界；有工具执行时，必须位于完整批次之后。
- 默认在可回退的对话上下文开头注入固定的 checkpoint 0，表示“从头开始”的起点锚点，不计作普通批次检查点。启用 dynamic-skill 时，0 位于其初始注入块之前；该技能块紧邻首条用户输入之前。system prompt 等宿主基础指令留在 0 之前，不属于回退范围。
- 第一个普通 checkpoint 是 1，放在初始用户输入之后、第一次模型生成之前；之后按完整工具批次等正常边界分配 2、3……。
- 回退到 0 时，初始用户输入也纳入对话历史候选，不能因起点边界而漏掉；实际注入按分层容量规则处理，其中最后一轮的 user 正文必须全文保留。
- 非零 checkpoint 的正常生成位置是：真实 user input 之后，以及整个工具批次的 tool result 全部到齐之后；均在下一次模型生成前注入。
- 一个 assistant 回复中的所有 tool call 属于同一批次。并行工具全部结果到齐后只建立一个边界，不在 call/result 之间或单个工具结果后提前插入 marker。
- assistant 消息之后不单独建立 checkpoint：包含工具调用时等待完整工具批次；纯文本最终回复后等待下一条真实用户输入，再建立边界。
- 技能注入、对话历史块、Host 续跑 message 不视为新的真实 user input，不各自触发额外编号；backtrack 完成交接及技能更新后统一建立一个续跑 checkpoint。
- marker 是 Host custom 状态消息，不伪装成用户真实指令；内容以不可变自定义 entry 保存，在 context hook 中按有效视图投影。
- 地址必须与对应内容一起出现在模型上下文中，不能仅在末尾给出脱离位置的编号列表。
- 普通回退（目标大于 0）不重置计数器，新 checkpoint 沿当前编号轮次中最新已分配编号继续，同一轮次内不复用编号。
- **backtrack 中仅回退到 0 重置编号**：成功后开启新的编号轮次，交接及技能更新之后的新 checkpoint 必须是 1，随后为 2、3……。此外，成功 compact 在其内部重建上下文时重新生成 checkpoint，按新的编号轮次从 0、1 开始。
- 成功回退后，保留前缀中的编号不变，被收起后缀的 checkpoint 失效。普通回退后的有效编号允许跳跃，不为补齐序列重新编号。
- 目标必须按发起请求时的有效上下文映射解析。编号仅在一个编号轮次内唯一，不能仅按数字在完整历史中查找目标。
- 不能借已失效的 checkpoint 重新引入已移出上下文的探索过程。保留前缀中的 checkpoint 是否仍有效，取决于其边界能否继续准确映射。
- 原生 compaction 或用户主动切换分支等使目标不再可用时，明确拒绝，不能悄悄近似到其他位置。
- 同一边界上的请求重试不应重复分配 checkpoint；新输入和新工具批次需要新边界。
- marker 记录当时的容量快照。历史 marker 不更新，不因当前水位变化而改写旧前缀。

初始注入顺序：

```text
宿主基础上下文（稳定前缀，不属于回退范围）
→ checkpoint 0（固定起点）
→ dynamic-skill 初始注入块（启用时，位置固定）
→ 初始用户输入
→ checkpoint 1（第一次生成前）
→ assistant（工具调用）→ 全部 tool results
→ checkpoint 2
→ assistant（工具调用）→ 全部 tool results
→ checkpoint 3
→ assistant（纯文本最终回复，不追加 checkpoint）
→ 下一条真实 user input
→ checkpoint 4
```

普通 checkpoint marker 示例：

```text
[checkpoint 20 | context 100K/300K 33%]
```

checkpoint 0 在同一有效上下文中只保留一个起点标记，不在每次请求或每次用户输入时重复追加。具体消息载体仍需确保起点锚点与普通检查点的语义可区分。

### 编号轮次与有效集合

例如当前轮次已生成到 35：

```text
回退到 20：… 20 → 交接及技能更新 → 36 → 37 …（沿当前轮次继续）
回退到  0：   0 → 重建的技能块 → 分层对话历史 → 续跑 message → 1 → 2 …（开启新轮次）
```

- 普通回退到 20 后，21～35 留在历史中，但从有效目标集合移除；其 marker 不再随已收起的后缀进入模型上下文。
- 回退到 0 后，旧轮次的非零 checkpoint 全部失效。保留目标 0 对应的前缀及边界作为新轮次的起点，不重写其历史 marker；新 1 与旧 1 是不同的 checkpoint 实例。
- 编号重置不新建 session、不切换分支、不清除技能状态或历史记录；同样触发一次技能结算与追加更新。
- Host 持久化内部编号轮次、该轮次的已分配上界及当前有效映射。实例身份由 session、轮次及编号共同确定，或使用等价的独立历史地址。
- 轮次只是内部身份，不增加工具参数；模型仍调用 `backtrack({ checkpoint, message })`。
- Host 将调用绑定到编号轮次及发起调用的 assistant/tool-call 身份，提交时检查目标节点仍有效。旧轮次的调用不能被重新解释成新轮次同号目标，重复调用按事务/调用身份幂等处理；不比较完整请求与原始历史的内容是否一致。
- 恢复会话时恢复最新已提交的轮次和该轮次计数，不取所有轮次的历史最大编号。普通回退仍不能按剩余有效目标的最大编号重置计数。
- 同一轮次内用户主动切换分支也不能复用已分配编号；需从持久化分配记录恢复该轮次上界。reload 或恢复本身不隐式开启新轮次；成功 compact 则在其内部重建流程中显式建立新的编号轮次。
- 对话记录块中提及的旧轮次编号或失效编号只是历史引用，不是可调用地址；指导模型以当前有效 Host checkpoint marker 为准。
- 失败或取消的回退不改变有效目标集合，也不开启新轮次。回退到 0 的重置必须与变换提交关联，恢复或重试不能重复重置。
- 不向模型注入全部历史编号清单；普通回退只保留有效目标，编号增长不代表上下文必须积累。
- compact 后旧轮次的 checkpoint（包括旧 0）全部失效，使用 compact 内部重新生成的新 checkpoint；旧请求不能按新轮次的同号目标重新解释。其他情况下目标失效仍应拒绝，不仅为重置编号而制造替代目标。

持久化映射至少需要 checkpoint 编号、内部编号轮次、所属 session、历史边界地址、有效前缀的节点引用、原始节点消费游标及容量快照。历史地址用于定位来源，不是要求宿主跳转的导航目标。还需定义原生 compaction、用户主动切换分支和 fork 后的有效性校验及编号衔接规则。

## 4. 工具参数与知识边界

目标接口改为：

```ts
backtrack({ checkpoint, message })
```

两个字段必填：checkpoint 为非负安全整数，message 为非空白文本。description 和 knowledge 已移除；旧四参数调用会明确拒绝，不静默接受或自动创建知识文件。

| 参数 | 语义 |
| --- | --- |
| checkpoint | 已由 Host 展示、且当前仍有效的目标编号；目标 checkpoint 及之前的当前有效上下文完整保留，不改写，不复活此前已收起的原始历史 |
| message | 交接从目标 checkpoint 之后做过的事情、看过的内容、学到的经验、试错教训，以及回退后的下一步计划；追加到继续上下文，不作为技能正文保存 |

### Tool description：主动控制上下文水位

工具说明应明确引导 Agent 根据任务难度管理上下文占用，而不是等到窗口接近耗尽才 backtrack：

| 工作类型 | 建议上下文占用区间 |
| --- | --- |
| 简短工作 | 0-20% |
| 标准工作 | 0-40% |
| 困难工作 | 0-80% |

- 占用比例指受管有效视图、system 与 active tools 的估算值占 context window 的比例，不含其他扩展临时注入，不是最终请求实测，也不使用原始 session 文件大小。
- 区间是建议，不作为工具调用的硬门槛。
- 探索阶段完成、工具过程已被消化，或水位接近相应上限时，先通过 dynamic-skill 固化需要保留的知识，再 backtrack，给后续工作留出空间。
- 容量反馈为估算或过时时按其准确度使用；不可获取时不编造百分比。

实际模型可见的英文说明以 [`src/tool-description.ts`](../src/tool-description.ts) 为准。主说明仅介绍保留/裁剪行为，以及主动水位管理、话题切换和完成支线回归主线时的使用时机。参数说明定义 checkpoint 前缀和 message 的工作交接内容。分层数值、估算范围和宿主适配细节留在文档，不反复注入。

宿主在启动及 reload 的 session_start 阶段，通过公开的 dynamic-skill 上下文服务判断是否启用，并刷新工具定义。仅启用时加入技能保存和读取指引，不让模型自行判断；两个扩展的加载顺序不影响结果。

### 回退前固化知识

知识保存从 backtrack 内部事务移到调用之前，由 Agent 使用普通 write/edit 保存或更新 dynamic-skill 管理的技能。

启用 dynamic-skill 时，工具说明提醒：回退前保存被压缩部分中的可复用知识、经验和试错教训。回退后的技能目录仅提供描述，不自动展开正文；关键信息应在 backtrack message 中重复强调，或加入“读取 xxx skill 获取 xxx 信息”的指引。

执行顺序：

```text
探索 → 整理将被回退内容中的知识 → write/edit 技能 → 确认保存有效
     → 单独 backtrack({ checkpoint, message }) → 结算并追加技能状态 → 继续
```

约束：

- backtrack 不再创建会话旁的 backtrack-<datetime>/SKILL.md，不维护另一套知识索引或条目生命周期。
- 不再存在“本次 knowledge 自动展开、旧 knowledge 折叠为 description”的逻辑；需要正文时按技能目录使用普通 read。
- 技能可保存当前项目的调查结论，不限于通用方法；仍应注明适用范围、版本及必要证据，避免将暂时结论当作永久事实。
- 不强制每次新建技能，不把所有新知识放成根技能；按技能树规则选取位置并优先合并更新。
- 保存失败或技能校验未通过时，应先修复，不把失败的写入当作知识已固化。Host 无法仅凭出现一次 write 就证明知识完整，初版不以“必须调用过 write”作为充分校验。
- 知识保存是回退前的独立文件操作；之后回退失败或取消，不撤销已保存的技能。
- message 是目标 checkpoint 之后这段工作的执行交接，必须说明做过什么、看过什么、所得经验、试错教训与回退后的下一步计划。保留相关约束、外部状态和必要技能路径；概述与本次继续工作相关的结论，不用整篇知识文档代替交接。
- 不为确认启用而重复读取已经展开的技能正文，也不等回退完成后才提醒保存。

## 5. 连续历史与有效上下文

必须区分两个视图：session 历史是发生过什么，模型上下文是本次请求需要看到什么。

```text
session 历史（始终沿当前历史追加）：
用户输入 → checkpoint 20 → 探索过程 → 保存/更新技能
         → backtrack 调用及结果 → backtrack 记录
         → 技能结算/状态更新 → 新 checkpoint → 后续对话

回退后的模型上下文：
保留前缀
→ dynamic-skill 更新（普通回退为差分；回退到 0 时重建技能块）
→ 对话历史（原始 session 中目标 checkpoint 到 from 之间的 user/assistant 正文）
→ 续跑 message
→ 新 checkpoint
→ 继续生成（需要知识正文时按需 read）
```

### 5.1 上下文变化的范围

- 对话历史候选从原始 session 的完整回退区间提取，包括区间内已被先前 backtrack 收起的 user/assistant 对话，再按分层容量规则裁剪并正序展示；thinking、tool call、tool result 不原样留在新的执行上下文中。
- 对话记录块标明原始角色和历史性质，不把历史 assistant 文本提升成新的用户指令。
- 图片只随原文完整保留的用户消息保留；消息截短或省略时不保留其图片。完整消息保持原始图文内容块顺序；保留图片的容量单独估算，不计入文字历史的 10K 分层预算。其他尚不支持的非文本类型明确报错，不静默丢弃。
- 原始后缀留在同一条 session 历史中，不归档到另一分支、不删除、不重写。TUI 可以像 compact 一样展示边界标记，但不能把后续对话表现为从旧节点重新开始。
- 已保存的技能文件不随后缀收起而消失；其发现和列表展示由 dynamic-skill 负责，必要路径可由 message 携带。不额外重写保留前缀中的技能读取结果。
- 追加了记录或 TUI 显示折叠，不等于模型实际上下文已改变。必须验证下一次真实模型请求。

### 5.2 第二块注入上下文：对话历史

这块内容只包含本次被回退区间中的 user/assistant 对话正文及用户原始图片，与 dynamic-skill diff、续跑 message 分开。不保存全部 session 对话副本，也不是对探索过程再次生成摘要。

#### 来源与边界

- `from` 是本次 backtrack 固定的来源/截止边界；`checkpoint` 是目标边界。from 由 Host 记录，不增加工具参数。
- 两个边界都解析为原始 session 上的确定位置，不能只使用可能跨轮次重复的显示编号。
- 取原始 session 当前历史路径上的区间 `(checkpointBoundary, fromBoundary]`，按从早到晚的顺序提取。目标边界及之前的内容属于保留前缀，不重复收录；from 之后的新内容不属于本次历史块。
- from 的记录需对应本次安全完成的工具批次，且在提交前复核竞态。后到达的用户输入不能被悄悄吞进已准备的历史块。
- 数据源是原始 session 条目，不是已应用 backtrack/compact 的模型消息数组，也不是上一次渲染出的对话历史块。

#### 提取规则

- 提取区间内所有原始 user 和 assistant 消息的正文作为候选，不按重要性筛选、不额外摘要，不仅提取“最终回答”；最终输出再应用下文的确定性分层保留规则。
- 保持原始顺序、角色及消息边界；assistant 同一消息中的文本块按原顺序提取，thinking 和 tool call 不纳入正文。
- tool result、checkpoint marker、技能列表、结算状态、回退记录及 Host 生成的旧历史块不作为 user/assistant 原始正文再次收录。
- 先在 session 层识别原始消息及来源，不能因为 provider 最终把 Host custom 消息转换成 user 角色，就将这些注入内容误算为用户对话。
- 没有正文的纯工具调用或纯 thinking 消息不产生空对话项。纯图片 user 消息在其消息被保留时保图；图片以宿主支持的原始内容块承载，不转换成占用文字预算的 base64 文本。
- 原文相同的不同消息都独立参与分层保留；去重依据来源条目身份，而不是文本内容。单次历史块中每个来源消息最多出现一次。

#### 包含 backtrack 中的 backtrack

例如原始 session 中：

```text
checkpoint A → 对话 X → checkpoint B → 对话 Y
             → backtrack(B) → 对话 Z → 本次 backtrack(A)，from 在此
```

本次分层处理的候选包含 X、Y、Z 中全部 user/assistant 正文，顺序与原始 session 一致。即使 Y 在第一次 backtrack 后已经不以原始消息形式进入模型请求，也不能在本次提取中遗漏；其最终保留精度仅由本次分层容量决定。

原始条目本来就保存在连续历史里，因此无需递归解析旧历史块；直接提取本次完整区间即可。先前生成的历史块如果在本次被收起的区域中，由本次新历史块替代，不产生“历史块嵌套历史块”或重复复制。

这与执行上下文的裁剪使用不同的数据源：**保留前缀依据当前有效上下文，对话历史依据原始 session 区间。** 恢复的是该区间的对话正文，不是重新引入其工具执行过程。目标之前且未被本次收起的历史块仍属于保留前缀，不为重建新块而改写。

#### 分层容量

从最新消息向更早消息分层分配预算，最终仍按原始时间正序打印。K 采用十进制，即 1K = 1000。

| 层级（由新到旧） | 输出预算（估算 tokens） | 每条消息的正文保留方式 |
| --- | ---: | --- |
| 最近层 | 5K | 原文 |
| 第二层 | 3K | 首 100 tokens + 中段省略标记 + 尾 100 tokens |
| 第三层 | 1K | 首 20 tokens + 中段省略标记 + 尾 20 tokens |
| 第四层 | 1K | 首 10 tokens + 中段省略标记 + 尾 10 tokens |
| 更早内容 | 不再保留正文 | 在历史块开头打印 `[N turns omitted]` |

- 每层预算按裁剪后实际注入文本估算，不是原始历史区间的长度；角色标签、分隔换行及省略标记也计入。四层通常合计目标为 10K tokens，仅针对本次对话历史块，不含技能差分、message 或保留前缀。
- 至少最后一轮的 `user:` 正文必须全文保留。它不因层级边界而变成首尾摘录或整条省略；完整保留的优先级高于容量预算，必要时允许超过 5K 最近层及 10K 总目标。
- 如果本次区间没有 user 消息，不从区间外复制一条来满足此规则；区间外的用户上下文仍按保留前缀处理。
- 其余内容越旧，保留精度越低。每条消息只出现一次，不在相邻层重复打印，也不把预算耗尽后的更早内容偷偷转移到 message 中。
- 短消息直接全文保留，首尾重叠时不重复，不产生没有实际省略内容的标记。
- 原始 session 正文始终完整保留；分层裁剪只影响本次注入，下次回退仍从原始区间提取后重新分层，不在已经截短的旧文本上继续截短。
- 以整条消息为分层单位，不把一条消息拆成多条展示。按当前层格式渲染后放不进剩余预算，就转到下一层按更短的首尾规则处理；仍放不下则继续降级，超过最后一层后省略其文字。
- 从新到旧进入更低精度层后，不用更早消息回填上层的剩余空间。最后一轮 user 是例外，始终全文保留，不因放不下而降级；该例外不使更早内容重新回到高精度层。
- 截短或省略的消息不保图，不生成脱离原文的图片占位行。较低层中的短消息若仍保留全文，则仍保图；判断依据是否实际截短，而不是层号。最新 user 强制全文保留，因此保图。
- 区间两端不完整轮次的计数细则需通过测试明确；仍有正文片段的轮次不能计作整轮省略。消息及其图片均被省略时，按整轮是否还有其他可见消息计数。

#### Token 估算

容量和首尾长度统一使用估算 token，不以 words 或原始字符数直接充当 token，也不依赖特定模型的 tokenizer。

初始折算建议如下，系数集中配置，具体值在实现测试中校准：

| 字符类别 | 初始估算方式 |
| --- | --- |
| 中文 | 每字 1～1.5 token |
| 英文字母、数字 | 每 4 字符 1 token |
| 标点、符号 | 每个 1 token |
| 空白、换行 | 单独累计估算，不忽略；初始可按每 4 字符 1 token |

- 中英文混合内容按各自类别累计；预算判断、首尾截取和省略量计算使用同一估算器，不在恢复时换用另一套口径。
- 按 Unicode 字符及安全文本边界截取，不能切坏代理对、组合字符或 emoji；其他字符类别需有明确回退规则。
- 省略 token 数只计算被移除的原文，标记本身另外计入输出预算。
- 这是容量近似值，不是 provider 实际 usage。省略标记为简洁不打印 `about`、`~` 或“约”，不因此把内部估算升级为精确计量。

#### 英文输出格式

```text
[12 turns omitted]
user: beginning[800 tokens omitted]ending
assistant: beginning[2.4K tokens omitted]ending
```

- 保留原始消息顺序，每条以小写 `user:` 或 `assistant:` 开头，不强制合并成交替的一问一答；正文允许多行。
- 中段省略只使用 `[N tokens omitted]`，不叠加 `...` 或其他说明。
- 更早的整轮省略只在开头使用一次 `[N turns omitted]`；一轮以原始 user 消息为起点，包含其后至下一条 user 之前的 assistant 消息。只有整轮正文不再展示时才算入整轮省略数，消息中段截短不算整轮省略。
- 没有对应省略时不打印标记。
- 数字不超过 2000 时直接打印整数；大于 2000 时采用十进制 K，最多保留一位小数，移除末尾 `.0`：`2000 → 2000`、`2400 → 2.4K`、`10000 → 10K`。该显示规则用于 tokens 和 turns，内部预算与计数仍保留未格式化数值。

### 5.3 追加回退记录与恢复

- 在当前 session 末尾追加一条可持久化的 backtrack 记录，描述本次上下文变换，不移动历史 leaf 到旧位置。
- 记录至少能关联事务身份、目标 checkpoint 的轮次、编号及其历史边界地址、来源 assistant/tool-call 身份、处理区间截止位置、续跑 message 和重建所需的数据或引用；具体载体及格式待运行时验证。历史块需保存渲染结果或可稳定重放的策略版本/估算参数，避免配置变化改写已经注入的内容。
- 连续 backtrack 的目标校验、保留前缀与执行上下文裁剪基于上一次变换后的有效上下文；对话历史块则从原始 session 的确定区间重新提取，包含区间内先前 backtrack 的对话。两条路径不得混淆，不能因恢复正文而重新引入工具过程。
- 恢复会话时从持久化记录重建同一有效上下文，而不是只恢复原始消息数组。不得在每次重建时再次追加 message、结算或触发续跑。
- 新用户输入和后续工具交互继续追加在当前历史末尾，并正常进入后续模型上下文。
- 原生 compact 应与此有效上下文保持一致，不能在摘要或保留尾部中重新带回已排除的原始探索过程。具体宿主接口和执行时序列为 P0 验证项。

### 5.4 Compact 内部重新生成 checkpoint

checkpoint 重建直接嵌入 compact 的上下文重建流程，不要求用户再执行命令，也不额外发起一次 backtrack。

- compact 成功生成新上下文后，使旧轮次的 checkpoint 全部失效，并创建新轮次。
- 在新上下文的起点生成 checkpoint 0，仍位于 dynamic-skill 注入块之前；普通检查点从 1 开始，按 user input 后及完整工具批次后的安全边界重新生成。assistant 消息之后不单独打点。
- 先识别旧 Host marker 并从新投影中排除，再生成新 marker，不能同时把旧编号和新编号当作有效地址。原始 session 中的旧记录不修改。
- 新 checkpoint 映射到 compact 后的有效上下文及其来源，而不是继续使用 compact 前的旧边界。回退到新 0 不能绕过 compact 恢复此前已被排除的工具过程。
- 在 compact 完成、下一次模型请求之前使新映射和注入结果就绪；既有技能 compact 结算只发生一次，不能因生成 checkpoint 再额外结算。
- compact 失败或取消不重置编号；恢复已完成的 compact 时重建其持久化结果，不重复创建轮次或重复插入 marker。
- 此流程不额外调用模型，不改变 compact 原有的手动/自动续跑语义。

## 6. Dynamic-skill 结算与追加更新

### 6.1 固定注入位置与从头重建

dynamic-skill 需要重构初始注入位置：不再无条件放到整个消息数组开头，而是放在**首条用户输入之前的最后位置**。这次注入建立后，位置及内容固定，不随后续 user 消息移动，也不在每次模型请求时重新搬到最新 user 前。

```text
首次：稳定前缀 → checkpoint 0 → skills → user A → checkpoint 1 → assistant
随后：稳定前缀 → checkpoint 0 → skills → user A → … → user B → …
```

- 同时启用 backtrack 时，其 checkpoint 0 位于 dynamic-skill 初始注入块之前；单独启用 dynamic-skill 时保留同样的固定位置语义，只是没有 checkpoint 标记。
- 初始技能块和后续追加的技能 diff 都位于 checkpoint 0 之后。因此成功回退到 0 时，它们都落入重建范围，而 0 之前的稳定前缀保持不变。
- 回退到 0 后，按本次结算结果重新生成技能块（active、pending 及必要指导），放在 0 后、对话历史与续跑 message 前。不为保持“贴着 user”而伪造新用户输入。
- 重建是重新生成模型可见目录，不是清空 LRU、访问记录或技能文件；旧注入记录也仍留在原始 session 中。
- 旧目录被整体收起后，超容量候选不再因为旧目录仍可见而被保护，可以按容量转 pending 并展示预告；不能跳过预告直接逐出。
- 普通非零回退保留目标之前的技能块和 diff，继续执行全局可见性去重、差分注入及软容量规则。
- reload/compact 或恢复需识别原注入锚点及保留范围，不能仅为刷新状态就移动/覆盖仍在有效上下文中的旧技能块。真正重建的区域可建立新的技能块，具体生命周期适配仍需验证。

### 6.2 结算时机

成功 backtrack 触发一次技能结算，复用 dynamic-skill 的访问与晋升规则，但溢出转 pending 必须考虑回退后仍可见的技能描述，允许 active 暂时超过容量。失败、取消及重复通知不能额外推进队列。

必须覆盖即将被收起的探索期间的有效访问，尤其包括回退前为固化知识而成功执行的 write/edit。结算需能发现这些新建或更新的技能，根技能仍按免容量规则处理。

由于不切换分支，访问记录仍完整保留在当前 session 历史中。dynamic-skill 应从真实历史中按结算边界统计，而不是从已经裁剪的模型上下文统计；后续结算不能重复消费此前已结算的访问。

建议采用准备与提交分离的协作流程，具体 API/事件名称待定：

1. **准备**：由 dynamic-skill 从连续历史中收集截至本次完整工具批次的访问与既有结算状态；结合本次计划保留的有效上下文，确定仍可见的技能描述集合，再计算队列与注入差分。此时不持久化新的结算、不逐出技能。
2. **提交**：backtrack 提交本次上下文变换后，由 dynamic-skill 将结算状态追加到同一 session，并准备模型可见的追加更新；二者就绪后才发送下一次模型请求。
3. **取消**：回退未应用时丢弃准备结果，保持原有结算状态。

协作须能关联 session、事务身份、访问统计截止位置、计划保留的上下文及提交位置，以支持幂等和恢复。backtrack 提供上下文保留范围与生命周期确认；dynamic-skill 负责识别仍可见的技能描述、计算队列及注入差分。backtrack 不解释技能队列内容。

### 6.3 全局可见性与追加差分

普通非零 backtrack 后追加的是 **dynamic-skill diff（new active、new pending）**，不是最新 LRU 全量快照，也不是要求模型用新列表覆盖旧列表。回退到 0 时，旧技能块位于重建范围内，按 6.1 节重建目录。

先确定回退后仍保留描述的技能集合 `visible`：

- 检查最终保留的整个有效上下文，包括开头的技能目录、后续所有未被回退收起的技能注入记录；不能只看最近一次列表。
- 同一技能的任意一份描述仍在，就视为已经注入，即使其他副本被收起。
- 仅存在于 session 原始历史、但已不进入模型上下文的描述不计入 visible。
- 技能身份及注入来源应可追踪，避免只靠 description 文本相同与否判断；具体记录方式待实现。

完成考虑可见性的 LRU 结算后，生成：

```text
new active  = settled active  − visible
new pending = settled pending − visible
```

注入约束：

- 描述已经在 visible 中的技能，不重新打印 active，也不打印 pending；即使它已经离开 LRU，也不补打通知或删除旧描述。
- 描述全部被收起或尚未注入的技能，才按结算后的 active/pending 身份补充。
- 技能既不在 visible，也不在结算后的 active/pending 中时，不为保留知识而重新引入；文件仍可通过已知路径读取。
- 差分在继续上下文末尾追加；为空时不需要追加空更新块。
- 不修改旧技能提示、不在原位置替换列表、不改写历史 read 结果。同一历史位置的已保留内容保持不变。
- 同一结算差分只追加一次；恢复、请求重试及多次 context 回调不重复追加。
- 模型可见描述集合不等于 LRU 队列。完整队列状态由 Host 持久化，不能从本次差分单独还原，也不能将差分标题或数量冒充完整目录快照。

等到旧描述真正不再保留、上下文彻底重建时，再按当时的 active/pending 生成目录和预告。checkpoint 0 位于初始技能块之前，正是为了让回退到 0 能完整收起该块及后续 diff，而不改动更前面的上下文。其他回退及 reload/compact 仍须检查实际保留内容，不能假定旧目录一律消失。

这里的“不改动原始上下文”指 dynamic-skill 的状态更新方式，不禁止 backtrack 按既定规则收起探索后缀。backtrack 不再额外折叠旧知识条目或技能读取副本；完整历史始终保留。

### 6.4 容量软上限与 pending 条件

backtrack 结算时，容量是目标上限，而不是必须立即满足的截断长度。**不能先强行截断 active、移入 pending，再仅在输出时隐藏 pending。**

- 不再自动展示 Root Skills；加载 dynamic-skill 根技能时即可读到子技能索引。根及其直接子节点仍不进入 active，不占容量。
- 保留访问去重和二分递进晋升规则；按照 LRU 次序确定溢出候选。
- 若某个溢出候选仍在 visible 中，本次不将它转入 pending，而是继续保留在 active 的相对 LRU 位置。容量不足以容纳这些条目时，允许 active 长度超过配置容量。
- 只有本次不再保留描述的溢出候选，才可转入 pending，并通过 new pending 提示模型。
- 不因“描述还在”把技能当作重新访问、强制晋升或根技能；这里只延缓溢出转 pending。
- 后续回退或上下文重建使描述不再保留时，重新按当时的队列与容量判断，不能依据之前曾经溢出就直接逐出。
- 暂时超容量的 active 状态必须能完整持久化和恢复，不能被工具函数、序列化或下一次读取状态时悄悄截断；状态展示应如实报告实际长度和目标容量。
- 例如容量为 2，active 顺序为 A、B、C：若溢出候选 C 的描述仍保留，则 active 继续为 A、B、C，长度为 3；若 C 的描述已被收起，则可得到 active A、B 和 new pending C。

预告与逐出：

- 新进入 pending 的条目必须先向模型展示预告，不能在同一次结算中立即逐出。
- 只有已经展示预告、且后续结算前未重访的候选才可逐出；技能文件不删除。
- 仅按本次实际追加的 new pending 记录新的预告展示。由于 visible 去重而省略的 pending 不能记作本次已展示；既有真实展示记录继续有效。
- 历史遗留的 pending 或已逐出条目如果描述仍在上下文，不重复打印，也不因描述仍在而自动回到 active。延缓规则针对本次 active 溢出转 pending。
- 回退后的更新需正确记录预告状态，不能因上下文重建或历史重放错误地提前逐出或重复预告。
- 预告文案应把 backtrack 纳入下一次可能发生的结算边界。

重构前的 dynamic-skill 基线 context handler 会过滤旧的同类投影，再在消息开头注入当前列表；LRU 也按硬容量处理溢出。这两部分都需调整，不能只修改输出文案。需验证两个扩展的执行顺序不会删除、前移或重复注入差分，并验证超容量状态在后续 reload/compact 中的衔接。

## 7. Backtrack 事务与失败边界

目标顺序：

1. 校验参数、目标、会话状态及工具批次独占条件。
2. 分配事务身份，记录编号轮次和调用节点；准备对话记录及续跑 message，不在事务中创建知识文件。
3. 安全结束当前工具批次，确保 call/result 成对持久化；不能让旧上下文先生成下一轮回复。
4. 再次检查取消、新用户输入、排队消息、用户主动切换分支和 compaction 等竞态。启用 dynamic-skill 时准备技能结算。
5. 在当前 session 末尾追加 backtrack 记录，提交本次上下文变换；不删除历史，不跳转到目标 checkpoint。
6. 重建有效上下文，确保宿主下一次模型请求使用该视图；提交技能结算并追加状态更新。
7. 建立新 checkpoint，继续当前执行或触发一次续跑，不能同时启动两条生成链路。

需要区分至少三种结果：

- **未应用**：校验或准备失败，维持原有效上下文，不推进技能结算；正常的失败工具记录仍追加到历史。
- **已应用但未完成**：backtrack 变换已提交，但上下文重建、技能状态追加或续跑失败。明确报告部分完成状态，不自动重放整个回退。
- **已完成**：backtrack 记录、有效模型上下文及启用的技能结算更新均已就绪，已继续执行。

实现要求：

- backtrack 正常执行，不要求回退后 token 必须减少；即使不减反增也允许，不增加节省量或预计超窗的调用门槛。
- 回退后的有效上下文如果实际超出窗口，交给宿主既有的 compact 流程处理；不在 backtrack 内再实现一套容量兜底，也不因此重放已经提交的回退。
- 不为强行满足窗口而额外截断最后一轮 user 全文、删除完整保留消息的图片或修改已确定的保留规则。后续 compact 按其自身规则处理，并在内部重新生成 checkpoint。
- 工具不能在仅完成准备时宣称回退成功。
- 事务身份、关键进度和来源地址须可恢复，防止重复应用上下文变换、重复追加更新、重复结算和重复续跑。
- Agent 在回退前保存的技能属于独立的真实文件操作；取消回退不能声称这些操作也被撤销。
- 会话持久化、技能结算和模型请求不存在天然的统一事务；部分提交及崩溃恢复策略须显式设计。
- dynamic-skill 未启用与“已启用但结算失败”是不同情况，后者不能被静默当作未启用跳过。

## 8. Pi 运行时约束与待验证方案

基于项目当前使用的 Pi SDK 0.85.1：

- `context` hook 可以非破坏性地改变实际模型请求消息，是有效上下文投影的候选入口；历史记录仍可保留。
- `pi.appendEntry()` 可以持久化扩展状态，但不会自动改变模型消息。仅追加 backtrack 记录并不足以完成上下文变换。
- 工具和事件处理器获得的 session 接口为只读；不能通过类型强转或直接修改磁盘历史绕过宿主。
- 当前方案不需要 `navigateTree()` 或 fork；之前围绕分支导航的命令桥接方案不再作为实现前提。
- 必须验证完整工具批次结束、事件落盘、context 回调及自动下一轮之间的顺序，不能在工具 execute 内等待自身执行结束。
- 宿主的容量统计和原生 compaction 不一定使用 context hook 的投影结果，必须单独验证。不能只让普通生成看到短上下文，而压缩和恢复仍使用旧长上下文。
- “类似 compact”是历史与上下文的行为约定，不意味着直接调用默认摘要流程或伪造原生 compact 事件。使用自定义变换记录、宿主压缩能力还是其他公开扩展入口，需验证后选择。

首要 TODO 是验证“完整工具批次落盘 → 追加回退记录 → 重建有效上下文与技能更新 → 下一次生成”的闭环。优先验证能否沿当前 Agent 循环自然继续；若必须暂停再续跑，应保证不遗漏、不重复，并验证恢复及原生 compaction 的一致性。

协作接口已选用 `pi-dynamic-skill/context` 的版本化同步服务：事件总线仅发现对象，真正的 prepare/commit/project/shown 调用直接返回或抛错，避免 Pi EventBus 吞掉处理错误。compact 以原生 compaction entry ID 去重，支持两个扩展的任意加载顺序。

## 11. 验收标准

1. 一次用户输入驱动多轮工具交互，Agent 主动 backtrack 后继续完成任务，无需用户再次输入。
2. 下一次模型请求包含保留前缀、技能更新（普通回退为差分，回退到 0 为重建目录）、对话历史及续跑内容，不再包含被折叠的原始工具过程。历史候选来自原始 session 中 `(checkpointBoundary, fromBoundary]` 内全部 user/assistant 正文，包含区间内先前 backtrack 的对话；按分层容量生成输出，顺序正确且不嵌套复制旧历史块。
3. 同一 session 的原始对话历史连续追加，不跳转、不建立 backtrack 分支；工具配对不损坏，文件及外部操作不回滚。
4. 同时启用 dynamic-skill 时，探索期间有效访问（包括回退前固化知识的 write/edit）参与一次结算；根技能不占容量。已保存的知识在回退后仍可通过技能目录或 message 中的路径按需读取，不依赖 knowledge 参数。
5. 对比回退前后请求：被保留的旧技能提示没有改写；开头或任意保留记录中已含描述的技能，不重复打印 active 或 pending，即使已离开 LRU。只在后面追加缺失描述的差分，连续请求不重复追加。
6. active 溢出候选的描述仍保留时，不进入 pending，允许队列超过目标容量，持久化与恢复不截断。描述后来不再保留时才重新判断 pending；实际新增的 pending 预告得到展示，失败、重试、恢复不导致提前逐出或重复推进 LRU。
7. 连续多次 backtrack、原生 compact/reload 和恢复会话后，有效上下文、checkpoint、续跑交接及技能最新状态保持一致；已被移出的工具探索过程不会从原始历史重新进入模型请求，按区间恢复的 user/assistant 正文除外。
8. backtrack 只接收 checkpoint/message，不创建知识文件、不自动展开知识正文，也不改写保留前缀中的旧技能提示或读取结果。
9. 当前轮次已分配到 35 时回退到 20，新 checkpoint 使用 36；21～35 保留在历史中但失效且不再注入模型，同一轮次内不复用编号。
10. 初始上下文按“稳定前缀 → 固定起点 0 → dynamic-skill 块 → 用户输入 → 普通 checkpoint 1”注入；技能块不随后续用户消息移动。成功回退到 0 后，稳定前缀保持不变，旧技能块及后续 diff 被收起并重建目录，初始用户输入纳入历史候选，最后一轮 user 全文保留，新 checkpoint 必须为 1。session 历史和技能状态不清空，旧轮次非零 checkpoint 失效；恢复与重试不重复注入起点或重置编号，旧调用不会命中新轮次的同号目标。
11. 对话历史从新到旧按估算 token 分层：5K 原文、3K 首尾各 100、1K 首尾各 20、1K 首尾各 10，更早文字省略。消息放不进当前层时整条降级，不拆成多条。输出使用英文 `[N tokens omitted]` / `[N turns omitted]`，大于 2000 的数字用 K；最后一轮 user 全文优先于预算，恢复后渲染一致。
12. 用户图片仅随完整保留的原文消息保留，截短或省略消息不保图；完整消息保留图文交错顺序。保留图片容量独立估算，不计入文字的 10K 预算。

## 12. 实现中补充的决定与 SDK 边界

### 12.1 Pi 0.85.1 的 compact 适配

实测 SDK 的普通生成会经过 `context` hook，但 `prepareCompaction()` 从原始 session 构造摘要输入，`firstKeptEntryId` 也指向原始尾部。只改生成请求的投影会导致 compact 重新读到已回退的工具内容。

当前选择：在 `session_before_compact` 中将有效对话提供给宿主现有摘要器（排除可重建的 checkpoint 和技能目录，不排除实际技能读取结果或任务交接），追加一个非模型可见的边界 entry 作为 firstKeptEntryId，不保留 raw tail。保留宿主一次摘要调用、取消/重试/usage 流程；成功后在 `session_compact` 内完成技能结算及 checkpoint 重建。以 compaction entry ID 保证两个扩展的处理顺序不影响结果，也不重复结算。

**影响：安装此扩展后，compact 摘要整个有效上下文，不再按照 keepRecentTokens 原样保留尾部。** 这是 SDK 当前没有物化有效尾部公共接口下的明确折中，不是暗中恢复原始工具过程。未来若升级到提供该接口的 SDK，可保留准确的有效尾部。原生 compact 的最小可压缩长度、自动压缩开关等宿主限制仍然生效；backtrack 不另造兜底压缩器。

### 12.2 同步提交、恢复与失败

Pi 的 Agent 事件会等待订阅处理完成；tool_call 前当前 assistant 已持久化，turn_end 前整批结果已持久化。因此 execute 只记录 prepared 请求，turn_end 同步提交后由原循环自然继续，无须隐藏命令、navigateTree、额外 user 消息或私有 Agent 状态写入。

- 有效视图保存原始 entry ID 引用；checkpoint、技能块、历史和续跑内容是独立的不可变 block entry。恢复不重新生成旧块的文本。
- 核心语义与 `/tree` 相同：定位目标节点，取该节点的有效前缀，追加 backtrack 专属输入（技能更新、分层历史及 message），然后续跑。不同之处仅是保留连续 session，不实际移动 leaf 或新建 session。
- `cursor` 只记录最后消费的原始 session 节点；`view` 保存有效节点引用；checkpoint 是 view 中的固定边界。移除整段 `inputKeys` 指纹快照、额外 revision 及其一致性拒绝逻辑。旧快照按其之前最后一个原始节点恢复 cursor，不重放或改写历史。旧快照捕获的外部 custom 块按出现次数参与请求来源匹配，避免与当前注入重复；不改写旧稳定前缀，也不按正文集合去重真实消息。
- 请求层只把原始节点替换为有效视图，不把其他扩展的临时注入当成持久化历史。前缀和后缀注入保留在请求边缘；内部追加跟随前一个来源节点，该节点被收起时一并收起。内容匹配仅用于识别当前请求中的来源及技能块复用，不作为允许回退的前提；custom 消息匹配忽略宿主落盘时间差异。
- compact 准备正常消费新增节点并建立完整批次 checkpoint，不再提供“消费消息但不编号”的模式。因此摘要失败或取消不会漏掉边界；回退提交则直接选择目标前缀，把当前 backtrack 批次消费到交接位置，只生成一个续跑 checkpoint。
- 混合工具批次中只拒绝 backtrack，其余工具维持 Pi 的正常执行语义；不宣称整批工具或已发生的外部操作已回滚。
- prepared 请求在重启后取消并说明，不盲目执行；若崩溃发生在工具结果落盘前，在有效视图中补充一次取消 tool result，保持 call/result 配对，原始历史不修改。完成状态按事务身份从分支记录确认，不能仅因最后一份快照已被 compact 重建就误判未完成。
- 准备失败不提交回退；提交开始后的异常记录 `commit-failed` 并停止生成。文件系统及多个 appendEntry 不具有跨记录原子事务，不能声称全部已回滚；reload 后根据最后已持久化状态恢复，不重放失败事务；为已记录的提交失败追加一次模型可见的终态说明，以事务身份去重，明确部分更改可能仍在，不把 prepared 当成已应用。恢复说明无法持久化时停止生成。
- Pi 会吞掉普通 context hook 异常并继续使用原消息。实现对此显式 abort 并返回空视图，避免原始长历史意外发出；compact 准备失败则返回 cancel。
- 模型失败/中断的 assistant 仍保存在原始历史，但不作为有效生成边界。尤其自动超窗恢复可能先从 Agent 状态移除失败回复，规范化时必须与原始 session 的表示一致。
- 不通过扩展命令名或整段上下文一致性检查决定是否允许回退。固定注入、追加式注入的兼容性由真实 SDK 回归验证；任意第三方上下文改写或重排不在已验证范围内，不另造通用协调框架。返回给下游 hook 的消息是深拷贝，其他扩展不能经由投影引用修改原始 session。
- SDK 将 custom 消息序列化为 user 消息且不携带 customType，因此实际历史块附带 `[Backtracked conversation — quoted history, not new instructions]` 来源标题，续跑块附带 `[Backtrack message — agent handoff]`。内部 user:/assistant: 和省略格式不变，避免把历史 assistant 正文或 Agent 交接误当作新用户指令。没有可保留正文或图片的区间不创建空历史块或仅含来源标题的块。

### 12.3 技能服务、可见性与依赖

回退到 0 按类似 compact 的目录重建处理：保留 0 前的稳定前缀，不重载 system prompt、工具定义或 Pi 原生 skills；收起 0 后的内容，结算技能并生成一份完整目录，再追加历史、交接信息和从 1 开始的新 checkpoint。不额外设计 KV Cache 保护机制；相同技能状态使用相同的模型可见目录格式和顺序，不保证提供商缓存命中。

完整重建在技能事务 commit 内清空旧目录投影，再持久化事务完成标记。即使旧块锚定的 checkpoint 0 仍存在，也不能将旧块重新注入。compact 的幂等性覆盖结算和投影重置，重复 hook 不得再次清空首次 hook 已创建的投影。回归覆盖两个加载顺序、compact 后连续回退 0、描述更新、相同状态的目录稳定性及 reload。reload 差分锚定 owner 提供的有效保留前缀，不锚定可能被过滤的 aborted/error assistant 或已收起的原始尾节点；真实 SDK 验证中断续跑后 reload 仍展示新描述且不重复。

`pi-dynamic-skill/context` 的服务发现是同步的，实际方法调用直接传播错误，不把关键提交藏在 Pi 会吞异常的异步事件回调中。没有已启用服务时只执行独立 backtrack；已启用服务准备失败时不能当作服务缺席。

visible 使用技能块的结构化路径及来源元数据，扫描所有保留块，不把任意用户正文中引用的 description 或路径猜成一个新的技能目录。active 超容量状态原样持久化；新 pending 只有真正放入模型请求的块才记入预告，旧历史中的预告按原记录保留。

配套 dynamic-skill 的协作通过公开服务及集成测试对齐，不在每次同步时探测扩展命令名或猜测兼容性。部署仍应只加载一份配套版本；任意旧版或重复安装组合不属于支持矩阵。

配套的未发布代码通过 `vendor/pi-dynamic-skill-0.0.0.tgz` 固定，lockfile 校验完整性；真实 SDK 集成测试加载安装后的包。这样无需将开发中的代码假装固定到旧远端提交，也不要求使用者有相邻源码目录。后续正式发布时可替换为对应的不可变 Git 提交。

### 12.4 分层、图片与测试边界

- 估算系数选择中文及日韩字符 1.5、Latin/数字/空白 0.25、其他字符 1；图片初步按 1365 tokens/张估算，仅作容量提示，不声称精确。checkpoint 水位按有效视图、system prompt 和当前 active tool schemas 计算，标记只写 context 和数值，不附加 `~`；数值仍为估算，不包含其他扩展临时注入，不声称最终请求实测，也不另造后置 hook 或 provider 适配计量。
- 首尾按 grapheme 截取。最近 user 的全文预算预先预留；整条消息降级后不回填更早内容。最旧层预留整轮省略标记开销。
- 区间开头若只有上一轮遗留的 assistant 而没有其 user，不额外计为一个完整 omitted turn；不同来源的同文消息不按文本去重。
- 文字合并后参与分层分配；完整保留的有图消息输出原始图文内容块序列，不转成 base64 文本，也不把图片移到全部文字之后。截短或省略的消息不保图。保留图片及其必要承载开销可使整体超过文字预算。
- 无持久化会话可使用内存中的同一套 entry 引用机制；进程结束后不承诺恢复。持久化 session 已验证重新打开、reload 及 SDK fork/clone 的路径复制后保持同一有效视图；引用只指向该路径上此前的 entry。技能绝对路径不做跨机器自动迁移。
- 已验证真实 SDK 的自动工具循环、无 UI 续跑、原生 compact、超窗 compact-and-retry、两种扩展加载顺序及无凭据脚本 provider；另以真实 CLI 子进程验证 text、JSON 和 RPC 模式，并通过隔离临时目录的生产安装加载两个扩展。真实网络模型、人工 TUI 交互及掉电/磁盘写入失败的全阶段注入测试仍属于额外环境验证。

### 12.5 注入审查后的收敛决定

- 两项目均不注册 `before_agent_start`；当前没有为该第三方兼容场景修改 checkpoint 的必要。维持现有节点边界，不增加用户输入归属协议或通用附加消息重建机制。
- 模型可见标记只写 context，不引入 managed context 等额外术语。估算范围在文档说明：受管有效视图、system 和 active tools，不含其他 context hook 的临时注入。不新增计量框架，不以容量估算拒绝回退。
- 图片随完整原文范围保留；截短或省略的消息不保图。最新 user 全文保留，因此保图；完整有图消息维持原图文交错顺序。
- SDK 摘要器序列化对话为文本，本适配不保留 raw tail，因而 compact 后没有保留原文尾部，也不额外保图。若未来支持原样保留有效尾部，图片随该原文范围保留，不设独立的永久图片保留区。
