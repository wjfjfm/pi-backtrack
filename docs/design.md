# Backtrack 设计边界

Backtrack 改变模型的有效上下文，不撤销已经发生的操作。原始历史仍在当前分支；它不是 tree 导航、文件回滚或知识存储。

## 为什么交给原生宿主

仅在扩展的 context hook 中维护视图，会让普通生成、compact、恢复和分支重建使用不同历史。原生 backtrack entry 与 compaction 共用有效上下文重建机制，避免已折叠的工具过程再次出现。扩展只负责 checkpoint 和替代内容，不保存第二份完整 view。

这里必须区分两种数据来源：保留部分来自**当前有效上下文**；裁剪对话来自**指定区间的原始 user/assistant 正文**。后者允许重新裁剪对话，而不是递归裁剪旧历史块，更不意味着恢复工具执行过程。

## 职责边界

- **宿主**：完整工具批次、原子提交、上下文重建、compact、下一轮刷新和生命周期通知。
- **backtrack**：checkpoint 地址、折叠范围、裁剪对话和交接内容。
- **其他扩展**：通过宿主有效上下文和公共生命周期恢复自己的状态。dynamic-skill 的访问结算、描述可见性和淘汰策略不属于 backtrack。

扩展之间不导入、不发现私有服务、不交换私有事件，也不依赖加载顺序。消费者必须读取正在运行的宿主上下文，不能用自己依赖的旧 SDK reducer 重新解释历史。

## 必须保持的约束

- 不切断工具批次；持久提交之前不能发布成功。工具结果转换不是提交确认，消费者应使用提交后的生命周期事件。
- 保留 raw 尾部时，交接只在原始调用中存在，不再额外注入。checkpoint 编号沿用原身份，移除的编号不回收，避免保留尾部中的引用被重新解释。
- backtrack 的原子提交不包含其他工具的外部副作用，也不包含订阅扩展自己的持久化事务。
- 排队输入不阻止折叠，也不纳入折叠区间；完成后由宿主按原队列语义送达，不另行注入或复制。
- 容量数字只是估算，不含请求期 marker 或其他临时注入，不是调用门槛。实际超窗由宿主 compact 处理，不另造压缩器。

## 兼容与验证

需要配套的原生宿主，不能只升级扩展。旧 view 会话不自动迁移：其 raw 历史不能准确代表原有效上下文，宁可明确拒绝，也不能静默展开。继续旧会话应使用旧扩展，或另起会话。

`npm test` 覆盖真实 CLI、原生宿主、失败与恢复及扩展组合。原生源码由 `PI_NATIVE_SOURCE` 指定，默认相邻的 `pi-native-backtrack`；组合测试需要相邻的 `pi-dynamic-skill`，运行时测试可用 `PI_DYNAMIC_SKILL_EXTENSION` 替换。测试依赖不构成产品依赖。

旧测试按行为迁移：原 runtime 的 40 项用例保留在 native-runtime；旧 view 修复用例由明确拒绝旧格式、原子提交和真实失败结果测试替代，不再模拟已删除的私有记录。组合覆盖两种加载顺序、顺序/并行执行、默认/保留尾部及描述保留/折叠。

工具文案与参数以 `src/tool-description.ts`、`src/schema.ts` 为准，具体行为以实现和测试为准，不在文档复制。上下文变化的审计理由见 [注入审计](native-context-injection-audit.md)。宿主持久化限制见其 `packages/coding-agent/docs/native-backtrack.md`。
