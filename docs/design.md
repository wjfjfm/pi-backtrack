# 初版设计

## 已确定的方向

三个能力组合：自动 checkpoint、随文容量反馈、Agent 主动 backtrack。

采用 Kimi SendDMail 的逐步边界思想，借鉴 Pi 会话树保留原始路径。checkpoint 地址必须与模型所见内容同时出现，避免事后仅靠编号列表猜测边界。

## Checkpoint 语义

- checkpoint 指向一个完整执行批次之后、下一次生成之前的上下文边界。
- 初次生成也有 checkpoint，并保留触发任务的用户输入。
- marker 是 Host 生成的消息，不是用户真实指令。具体 Pi 消息载体须验证后确定。
- 编号在会话内单调递增且不复用；恢复会话后延续计数。
- 只允许回到当前路径上仍然有效的祖先 checkpoint；原生 compaction、分支切换等导致目标失效时明确拒绝。
- `20` 的 token 数是当时的快照，不代表回退后精确占用，后者还包括新摘要等内容。

## 工具参数与知识条目

`backtrack({ checkpoint, description, knowledge, message })`：四个字段必填，checkpoint 为非负安全整数，其余字段为非空白文本。

- description：知识的内容与用途，条目折叠后仍可见。
- knowledge：实际知识正文，本次 backtrack 后完整展开。
- message：仅追加到本次回退后的上下文，用于续跑，不存入知识条目。

每次 backtrack 收起旧知识条目和此前按需读取的副本，保留它们的 description；展开本次新条目。计划中的读取工具返回完整 knowledge，不返回 message；读取本身不触发其他条目折叠。

Tool Description 与字段指导文案集中在 `src/tool-description.ts`，当前为占位文本，另行完善。此处是设计约定，存储、投影与读取尚未实现。

## Backtrack 事务

1. 校验目标、description、knowledge、message 及工具批次独占条件。
2. 记录调用时的分支位置，等待当前批次安全结束。
3. 检查是否收到新的用户输入或发生分支推进；若存在竞态，取消操作并说明原因。
4. 保留原文及恢复地址，在目标边界建立继续分支，收起旧知识，展开本次知识并单独追加 message。
5. 同步宿主实际发送给模型的上下文，而不只是修改会话存储。
6. 建立新的 checkpoint，触发继续执行。

失败前不宣告成功；实现需要区分未应用、已应用但同步失败等状态，避免重复回退。

## 容量反馈

展示 used、window、比例及估算标记。优先使用宿主对当前请求的估计；只有上一轮 usage 时，必须补计后续内容或标记读数过时。不可获取时显示 unknown。禁止为刷新水位改写已有 marker。

## 验证重点

- 一次输入驱动多轮执行，每个批次只有一个 checkpoint，批次内不插入标记。
- Agent 无需额外用户输入即可调用 backtrack 并续跑。
- tool call/result 不被拆开；并列 backtrack 与普通工具时拒绝回退。
- 重复调用、无效编号、恢复会话与原生 compaction 不产生地址混淆。
- 折叠后的实际模型请求符合预期：保留前缀和摘要，移出原始后缀。
- 归档保留完整原文，文件及外部操作不被回滚。

## 后续问题

归档搜索/读取、是否支持中间区间、摘要质量评估以及缓存与费用基准，均不属于已实现能力。
